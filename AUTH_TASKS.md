# Авторизация и портфолио: реализованный контракт

Бэкенд и фронтенд уже связаны. Этот документ заменяет первоначальное задание по реализации авторизации.

## Сценарии и роли

Студент регистрируется, автоматически входит, загружает работу, видит только свои файлы, скачивает и удаляет их. Для загрузки выбирает предмет, тип, осенний/весенний семестр и начало учебного года; название необязательно.

Администратор входит через ту же форму. В панели доступны все работы, фильтр по владельцу, список студентов и управление предметами. Предмет с привязанными работами удалить нельзя. Публичной регистрации администратора нет; администратор не загружает работы от имени студентов.

## API

Поля JSON — camelCase. Ошибка: `{"error":"Сообщение"}`. Все изменения требуют `X-MUCTR-Request: 1`. Браузер отправляет cookie (`credentials: include`). Допустимые Origin задаются переменной `APP_ORIGINS`; токен не помещается в localStorage.

| Метод и путь | Доступ | Назначение |
| --- | --- | --- |
| GET /api/health | Все | Доступность PostgreSQL и MinIO |
| POST /api/auth/register | Все | Создать студента и сессию |
| POST /api/auth/login | Все | Войти, обновить cookie |
| POST /api/auth/logout | Все | Удалить сессию и cookie |
| GET /api/me | Вошедшие | Текущий пользователь |
| GET /api/disciplines | Вошедшие | Предметы |
| GET /api/work-types | Вошедшие | Типы работ |
| GET /api/drive | Вошедшие | Свои работы / все для admin |
| POST /api/files | Студент | Загрузить файл |
| GET /api/files/{id}/download | Владелец/admin | Скачать |
| DELETE /api/files/{id} | Владелец/admin | Удалить объект и запись |
| GET /api/students | Admin | Студенты и число работ |
| POST /api/disciplines | Admin | Создать предмет |
| DELETE /api/disciplines/{id} | Admin | Удалить неиспользуемый предмет |

### Регистрация

```json
{
  "firstName": "Иван",
  "lastName": "Иванов",
  "middleName": "",
  "email": "student@example.ru",
  "enrollmentYear": 2026,
  "password": "MyPassword123!"
}
```

Пароль: минимум 10 символов, максимум 72 байта UTF-8. Email приводится к нижнему регистру. Нельзя передать `role` или `studentId`: неизвестные JSON-поля отклоняются. `students`, `auth_users` и `auth_sessions` создаются одной транзакцией. Вход принимает только `email` и `password`.

Ответ регистрации (201), входа (200) и `/api/me` (200):
`{id, email, role, studentId, fullName}`. У администратора `studentId: null`.

### Загрузка

`multipart/form-data`: `file`, `disciplineId` (UUID), `workTypeId`, `semester` (1/2), `academicYearStart` и необязательный `title`. При работе через FormData не задавайте Content-Type вручную: браузер добавит boundary. Лимит файла — 25 МиБ. Ответ 201: `{id, name}`.

Владелец берётся из сессии. Метаданные заносятся со статусом `pending`, затем объект отправляется в MinIO и запись получает `ready`. Студенту без истории группы разрешена загрузка.

### Список и предметы

`GET /api/drive?q=...&subject=...&type=...&semester=...&page=1`.
Администратор дополнительно может передать `student=<UUID>`.
Ответ: `{files, total, page, pageSize, stats: {count, bytes}}`, размер страницы — 20.
`stats` относится ко всем доступным работам, `total` — к текущему фильтру.

Поля файла: `id`, `title`, `name`, `owner`, `studentId`, `disciplineId`, `disciplineName`, `workTypeId`, `workTypeName`, `semester`, `academicYearStart`, `fileSize`, `mimeType`, `uploadedAt`.

Создание предмета: `{"name":"Название","description":"Описание"}`. Повтор названия без учёта регистра/лишних пробелов возвращает 409.

### Ошибки

- 400 — неверные поля.
- 401 — нет действующей сессии / неверные данные входа.
- 403 — запрещённая роль или источник запроса.
- 404 — работа отсутствует или принадлежит другому студенту.
- 409 — email/предмет уже существует либо предмет используется.
- 413 — превышение размера файла.
- 415 — неподдерживаемый формат.
- 429 — превышено число попыток входа.
- 503 — временная недоступность БД/хранилища.

## Где продолжать работу

- Backend: `backend/auth.go`, `catalog.go`, `files.go`; маршруты и общие проверки в `main.go`.
- Frontend: `frontend/src/App.tsx`; API-клиент и типы в `src/api/driveApi.ts`.
- База: `02-auth.sql` и `04-portfolio-upload.sql`; тестовые аккаунты в `03-dev-auth-seed.sql`.
- Инфраструктура: корневой `docker-compose.yml`, ограниченные права MinIO в `infra/minio-policy.json`.
- Проверки: `backend/integration_test.go` и отдельный `compose.test.yml`.

Фронтенд показывает ошибки сервера вместо подмены данных демо-массивами. При 401 возвращает на форму входа. Кнопки администрирования отображаются только для admin, но окончательное решение всегда принимает API.

Следующие отдельные задачи: подтверждение email, восстановление пароля, квоты хранилища и антивирусная проверка загрузок. Запуск и локальные учётные данные описаны в корневом README.
